# relationship UI 表示要件（8本柱）

本書は `MutualInsightScreen` / `MutualInsightCard` の表示要件を確定するための仕様。
対象は `MutualUnderstanding` の8本柱。

## 1) 目的

- 肉厚化済みの正本（`1x1.ts`〜`9x9.ts`）を、読み切れる量で安全に表示する。
- 「まず全体像、次に詳細」の順で読める構造にする。
- 感情的に重い内容でも、ユーザーがコントロール可能なUI（折りたたみ・段階表示）にする。

## 2) 画面単位

- 画面名: `MutualInsightScreen`
- 主カード: `MutualInsightCard`
- 表示対象ペア: `selfType x otherType`
- 補助ラベル: `otherIsInferred === true` のとき「（推測）」を付与

## 3) 情報設計（表示順）

8本柱は以下の順で固定表示（意味の流れ優先）:

1. `status`（関係の現状）
2. `viciousCycle`（悪循環）
3. `cognitiveGap`（認知ギャップ）
4. `virtuousCycle`（好循環）
5. `respect`（相互尊重）
6. `responsibility`（責任分界）
7. `defer`（先送り論点）
8. `communication`（伝え方）

補足:
- 「責任分界」は責任の切り分け（誰が何を担うか）。
- 「先送り論点」は今すぐ決めない方が安全な話題。

## 4) 初期表示ルール

- 初期オープン（展開）: `status` と `summary` のみ
- 初期クローズ（折りたたみ）: 2〜8番
- 各セクションに `開く / 閉じる` の明示トグルを付ける

理由:
- 初見での情報過多を防ぎ、読み進める意図をユーザー側に残すため。

## 5) セクション内の表示仕様

### 5-1. status

- `good` / `bad` / `summary` を必ず表示
- 表示順: `summary` → `good` → `bad`
- `good` と `bad` は最大3件までを初期表示し、残りは「もっと見る」で展開

### 5-2. viciousCycle / cognitiveGap / virtuousCycle

- 各配列の表示上限（初期）: 2件
- 超過分は「もっと見る」で展開
- ラベルはデータ項目名をそのまま使わず、日本語化する
  - 例: `triggers`→「引き金」、`loop`→「連鎖」

### 5-3. respect / responsibility / defer / communication

- 小見出し＋箇条書きで表示
- 初期は各小見出し2件まで
- `communication.examples` は引用風スタイル（視覚的区別）にする

## 6) 文量制御（可読性）

- 1行の最大文字数は端末幅で自然改行（強制省略しない）
- ただしセクション全体高さが一定以上の場合、段階表示を優先
- 「もっと見る」展開後も「閉じる」で元に戻せること

## 7) 空状態・異常状態

- 該当配列が空: `（項目なし）`
- セクション全体が空: `（辞書未投入）`
- ペア取得失敗時:
  - 文言: `データを読み込めませんでした`
  - 再試行CTAを表示

## 8) 文言トーン

- 断定的・評価的表現を避ける（ガイドとして提示）
- 命令形より提案形を優先
- 技術ラベルは日本語優先、必要なら括弧で英語キーを併記

## 9) アクセシビリティ

- 折りたたみトグルは44px以上のタップ領域
- 見出しはスクリーンリーダーで階層認識できる構造にする
- 色だけで意味を分けない（ラベル併記）

## 10) 将来拡張（このフェーズでは未実装）

- 比較表示（例: `4x9` と `9x4` の差分）
- セクション単位の共有（コピー）
- 重要文のピン留め

## 11) 受け入れ条件（Definition of Done）

- 8本柱が指定順で表示される
- 初期表示は `status` 中心で、他は折りたたみ
- 各セクションで段階表示（もっと見る/閉じる）が機能する
- 空状態・エラー状態の表示がある
- `selfType x otherType` と「（推測）」表示が正しい
